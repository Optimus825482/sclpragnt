## Amaç

Tek-parola auth yerine **kullanıcı adı + şifre** ile çok kullanıcılı kimlik sistemi kurmak:
- **Admin**: kullanıcı adı `admin` (büyük/küçük harf duyarsız — `admin` ve `ADMIN` de kabul), şifre `518518Erkan` (ilk talebiniz).
- **Yeni "Kullanıcı Yönetimi" sayfası** (Sidebar menüsünde, yalnız admin görür): kullanıcı tablosu + Ekle/Düzenle/Sil (modal + confirm modal + sonuç bildirimi).
- **Ayarlar, Kullanıcı Yönetimi ve Raporlar sayfaları yalnız admin'e görünür**; normal kullanıcılar sidebar'da görmez, doğrudan URL'den girerse "yetkisiz" ekranı alır.

## Mevcut durum (keşif özeti)
- Auth tek parola: `POST /api/auth/login` yalnız `{password}` alıyor, `SCALPER_ADMIN_PASSWORD` env'iyle `hmac.compare_digest` (security.py:55). Session: imzalı cookie `scalper_session`, payload `{sub:"admin", exp}` (security.py:34-52), 12 saat.
- Global middleware `require_admin_session` (main.py:165-179) tüm `/api/*`'yi korur; public whitelist: `/health`, `/api/auth/status`, `/api/auth/login`.
- DB'de users tablosu **yok** (PostgreSQL tek backend). Frontend: AuthGate (login formu tek şifre), rol/username state'i yok, Sidebar MENU sabit, sayfa bazlı koruma yok.
- `backend/.env`: `SCALPER_ADMIN_PASSWORD=518518`, `SCALPER_SESSION_SECRET=replace-with-at-least-32-random-bytes` (placeholder), `SCALPER_COOKIE_SECURE=1`.

## Backend değişiklikleri

### 1. Migration — `users` tablosu
`backend/migrations/001_pgvector_schema.sql` sonuna (veya yeni `002_users.sql` + init çağrısına) ekle:
```sql
CREATE TABLE IF NOT EXISTS users (
  id SERIAL PRIMARY KEY,
  username TEXT NOT NULL UNIQUE,          -- küçük harfe normalize saklanır
  password_hash TEXT NOT NULL,            -- PBKDF2-HMAC-SHA256
  role TEXT NOT NULL DEFAULT 'user',      -- 'admin' | 'user'
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at DOUBLE PRECISION NOT NULL,
  updated_at DOUBLE PRECISION NOT NULL
);
```
database.py'ye `get_user_by_username`, `list_users`, `create_user`, `update_user`, `delete_user` fonksiyonları.

### 2. security.py — hash + rol
- `hash_password(pw)` → `pbkdf2_hmac("sha256", salt, iterations=~200k)`; `verify_password(pw, hash)`.
- `create_session_token(username, role, ttl)` → payload `{sub: username, role, exp}`; `verify_session_token` artık `sub=="admin"` sabitini değil, payload'daki username/role'u döndürür.
- `request_authenticated()` yerine/yanına `request_user()` → `{username, role}` veya None. **Not**: eski `sub=="admin"` kuralı kaldırıldığı için tüm mevcut admin-only API'ler artık herhangi bir giriş yapmış kullanıcıya açılır — bu yüzden aşağıdaki admin gate'i şart.
- Eski env-tabanlı `password_matches()` login'de kullanılmaz; DB'den doğrulama yapılır.

### 3. main.py — auth akışı
- `POST /api/auth/login`: body `{username, password}`. Username normalize (lower). DB'den kullanıcı bul; `is_active` değilse reddet; `verify_password`; başarılıysa token cookie (`sub=username, role`). Brute-force koruması (5/5dk) korunur, username+password ile.
- `GET /api/auth/status`: `{configured, authenticated, username, role}`.
- **Admin bootstrap**: uygulama açılışında (lifespan) `admin` yoksa oluştur — kullanıcı adı `admin`, şifre `518518Erkan` (kullanıcının ilk talebi; `.env`'deki `SCALPER_ADMIN_PASSWORD` değeri `518518Erkan` yapılır veya bootstrap bu sabiti kullanır).
- **Admin-only gate**: yeni `require_admin` dependency/middleware — `role == "admin"` değilse 403. Aşağıdaki yönetim endpoint'lerinde kullanılır.

### 4. Kullanıcı CRUD API (admin-only) — main.py veya yeni `routers/users.py`
- `GET /api/admin/users` → kullanıcı listesi (şifre hash'i hariç).
- `POST /api/admin/users` → `{username, password, role, is_active}`; aynı ad varsa 409.
- `PUT /api/admin/users/{id}` → `{username?, password?, role?, is_active?}` (kısmi güncelleme; şifre boşsa değişmez).
- `DELETE /api/admin/users/{id}` → sil (kendini/admin'i silmeyi engelle).
Hepsi `require_admin`. Yanıtlar `{ok, ...}` + Türkçe hata mesajları.

## Frontend değişiklikleri

### 5. AuthContext + AuthGate
- `AuthGate` login formuna **kullanıcı adı + şifre** alanı; `/api/auth/login`'e `{username, password}` POST.
- `/api/auth/status`'tan `{authenticated, username, role}` okunur; bir `AuthContext` (React context) ile `username`/`role` tüm uygulamaya verilir.
- Logout korunur.

### 6. Sidebar — rol bazlı menü
- `MENU` dizisine koşullu eleman: `role === "admin"` ise "Kullanıcı Yönetimi" (`/users`) linki.
- **Ayarlar ve Raporlar linkleri yalnız admin'e** gösterilir (normal kullanıcı sidebar'da görmez).
- Sidebar altında giriş yapmış kullanıcı adı + rol rozeti (opsiyonel, TopBar'a da konabilir).

### 7. Sayfa bazlı koruma
- `Kullanıcı Yönetimi` sayfası (`app/users/page.tsx`) + `Settings`/`Reports` sayfaları: bir `RequireAdmin` wrapper bileşeni — `role !== "admin"` ise "Bu sayfa yalnız sistem yöneticisine açıktır" ekranı (sidebar gizleme + URL koruması).

### 8. Kullanıcı Yönetimi sayfası (`app/users/page.tsx`)
- **Tablo**: Kullanıcı adı, Rol, Durum (Aktif/Pasif), Oluşturma zamanı, İşlemler (Düzenle/Sil butonları).
- **Ekle** butonu → modal (kullanıcı adı, şifre, rol seçimi, aktif).
- **Düzenle** butonu → modal (kullanıcı adı, yeni şifre isteğe bağlı, rol, aktif).
- **Sil** butonu → onay modalı.
- Tüm işlemler sonrası **sonuç bildirimi** (başarı/hata) gösterilir; tablo yenilenir.
