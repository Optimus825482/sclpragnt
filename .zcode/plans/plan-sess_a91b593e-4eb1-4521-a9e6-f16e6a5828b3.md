# BİRLEŞİK YÜKSELİŞ SİSTEMİ — Kur → Backtest/Replay → Canlı

## İlke (senin kuralın, bağlayıcı)
**Hiçbir şey backtest geçmeden canlıya dokunmaz.** Sıra: (A) sistemi kur → (B) replay/backtest ile doğrula → (C) ancak doğrulanırsa canlıya al.

## Keşif: iskelet ZATEN VAR (sıfırdan inşa yok)
- `combined_radar.py`: birleştirme çekirdeği (`build_combined_events` / `build_combined_candidates` / `build_unified_envelope`) — şu an **yalnız replay'de** kullanılıyor, canlıda değil.
- `combined_radar_replay_24h.py`: backtest harness'ı — **auto_paper B1-B4 çıkış merdivenini 1m mumlar üzerinde simüle eder**, net % (maliyet düşülmüş), MFE/MAE, hedef-dokunma verir.
- `unified_signals.enrich_candidates` (velocity+jump+early+rising füzyon), `master_surge.evaluate_master_surge` (4-katman **ortak karar** + `confluence_count`), `surge_learning` (adaptif per-symbol bias), `velocity_calibrate` (otomatik ATR), `database` symbol-target EMA.
- `combined_paper.py`: bağımsız defter şablonu.

## AŞAMA A — Sistemi kur (üretime DOKUNMADAN)
### A1. `backend/app/rising_pool.py` (saf, test edilebilir çekirdek)
- `build_pool(force=False)`: tüm motorlar → tek havuz: velocity (5/15/30/60) + momentum + squeeze + rising + **Global** (lead-lag + Global velocity). Sembol tekilleştir → `enrich_candidates` füzyon → `evaluate_master_surge` **ortak karar** (composite_index + confluence_count) → kalite/hedef/potansiyel. TTL önbellek (~25 sn).
- **Ortak karar kapısı** `is_genuinely_rising(c)` = *fiyat yukarı* (`ret3_pct>0` veya `passes`) **VE** composite_index ≥ eşik **VE** confluence_count ≥ N. Zayıf izleyici/füzyon-tek adaylar elenir.
- `UNIFIED_POOL_ENABLED` bayrağı — kapalıyken davranış birebir eski.
- Bu aşamada HİÇBİR canlı çağrı değişmez; modül yalnız import + test edilir.

### A2. `backend/app/pool_learning.py` (adaptif, replay'de doğrulanacak)
- Havuz eşikleri (kalite + "gerçekten yükselen" getiri + confluence_min) realize sonuca göre otomatik ayarlanır (mevcut `velocity_calibrate` deseni); mevcut `surge_learning`/EMA yeniden kullanılır.

### A3. Yeni bağımsız defter `backend/app/unified_paper.py` + DB + API + frontend panel
- `combined_paper` şablonu klonu; kendi cüzdanı/tablosu/lock'u; eski defterlerden **tamamen bağımsız**. Giriş tetikleyicisi: `is_genuinely_rising` adayları.
- Birim testleri + DB idempotent-DDL. (Henüz canlı beslenmez.)

---

## AŞAMA B — Backtest / Replay (karar burada)
### B1. Replay harness genişletme
- `backend/scripts/unified_pool_replay.py` (mevcut `combined_radar_replay` deseni + `rising_pool.build_pool` + `_simulate_ladder`):
  - 30–60 gün gerçek veri (sqlite klines + PG adaylar) üzerinde **walk-forward**: ilk %60 eğitim, son %40 sınav.
  - **İki akış karşılaştırılır:** mevcut (radar tek başına) vs **birleşik havuz + ortak karar kapısı**.
  - Metrikler: net EV/işlem (taker + maker), kazanma, payoff, fold stabilitesi, gün-gün, sembol yoğunlaşması, MAE>MFE kontrolü.
### B2. Adaptif öğrenmenin walk-forward doğrulaması
- Eşik öğrenmesi eğitimde fit, sınavda ölçülür; kazanç/zarar net raporlanır.
### B3. Karar raporu
- `docs/` altında sonuç; **eşik: net EV>0, t>1.65, 3-fold kararlı, yoğunlaşma<%10.** Geçmezse birleşik sistem canlıya ALINMAZ (bulgu raporlanır).

## AŞAMA C — Canlıya alma (yalnız B geçerse)
- `rising_pool` canlıya bağlanır: `_run_scan` + `_combined_scan_rows` havuzu okur (çift tarama biter); tek bildirim kanalı; WhatsApp aynı havuzdan.
- Yeni `unified_paper` defteri = tek paper portföy (push+liste aynı havuzdan besler). Eski `auto_paper`/`combined_paper` dokunulmaz, ayrı izlenir.
- Kademeli: önce gölge/log, sonra push/WhatsApp; her adımda tam test.
