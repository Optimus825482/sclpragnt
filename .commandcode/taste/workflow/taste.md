- A single-period parameter search is not evidence — overfitting must be explicitly guarded against, and the tool must make verification POSSIBLE: picking the best cell out of a 192-cell TP/SL grid over one 24h window is optimistically biased, so the finding must be re-run on a second, NON-overlapping period. When the replay window was hard-fixed to `now` (`since = until - hours*3600`), so that re-running the same grid on another period was impossible, an `offset_hours` window shift was added end-to-end (`build_report` → `run()` → CLI `--offset-hours` → the in-app job layer → a new "ÖNCE" input in the settings radar panel) rather than leaving the report merely admitting "one period isn't enough evidence". The decision rule is fixed BEFORE the run so the result cannot be reinterpreted afterwards (best cell still positive AND region structural → finding holds, a paper-change becomes legitimate; negative or weak/noisy → single-period artifact, production TP/SL unchanged). The out-of-sample run also keeps a distinct default output filename (`_oos24h`) so it cannot silently overwrite the baseline period's evidence, and the report header prints the measured period (`DÖNEM:` line + `← OUT-OF-SAMPLE` marker). Extended in a later round: the two periods must be compared BY THE TOOL, not by the user — leaving him to eyeball two reports side by side is treated as a gap to close, because a comparison performed by eye after seeing the numbers can be reinterpreted post-hoc. With `offset_hours > 0` the job now runs the base period automatically and emits ONE report with a single pre-fixed `KARAR:` line (DAYANDI / ZAYIF / DAYANMADI) plus whether the optimum's LOCATION is stable across periods (an optimum that wanders between periods means the "best cell" is a luck peak); the CLI gets the equivalent `--compare-oos` flag (and the comparison run must not overwrite the base period's JSON). Also: re-measuring the SAME (or nearly overlapping) window is explicitly NOT verification — a second run giving a consistent number is not independent confirmation ("aynı veriyi iki kez ölçmek bulguyu güçlendirmez"). Confidence: 0.7
