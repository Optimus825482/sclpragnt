# Taste — Infrastructure & ops

- The production Docker host runs many unrelated apps/services concurrently (Coolify/Traefik proxy plus numerous other projects' container stacks on the same host, some sharing ports). When fixing a fault in one app, the user explicitly wants the change scoped narrowly to that affected service so the rest of the network/apps are never disrupted ("o sunucuda çalışan bi sürü uygulamam var, komple networku bozmayalım") — prefer targeted operations (e.g., one service only, `--no-deps` recreate) over anything that touches the shared proxy, Docker network, or other containers. The user would rather have the assistant make the necessary docker-compose/config adjustments themselves than perform broad server-side network operations. Confidence: 0.7
- For disk/DB-growth problems, insists on MEASURING before deleting: the chosen path is always read-only diagnostics first (host `du -xhd1 /`, `docker system df`, Postgres `pg_database_size` / per-table `pg_total_relation_size` + live-vs-dead tuple counts, oldest-row dates), and the actual retention/deletion decisions are made from those real numbers rather than guesses — "tahminle silmek yerine önce ölçelim". The assistant is expected to run these via copy-pasteable commands the user executes (no direct server access) and to wait for the output before touching data. Confidence: 0.65
- Wants the application's Postgres data bounded by explicit retention windows instead of growing forever: historical candles + feature snapshots kept 21 days (ML training only looks back ~10 days, so older rows are dead data), and daily `pg_dump` backups kept 1 day instead of 7 on the disk-constrained host. Retention/pruning must cover ALL append-only telemetry tables (alerts, trace events, chat/memory logs), and deleting rows alone is not accepted as a fix unless space is actually returned to the OS (VACUUM). Reconfirmed when `decision_logs` — the largest live table (~8.5k rows/day, 1.46 GB TOAST, missed by every sweep) — was added to the pruning list at its own 90-day window with irreversible evidence rows (`strategy='AUTO_PAPER'`) preserved and the table added to the VACUUM list; the user approved applying it (together with the CI Python pin) with an immediate "UYGULAL IKISINE DE". Confidence: 0.65
- Deployment topology for scalperagent_v4: production runs on the remote Coolify host and AUTO-DEPLOYS from `origin/main` — a git push triggers the backend/frontend docker rebuild + redeploy, so pushing IS the production release. The local Windows dev machine has NO Docker and the app does not run there by default (nothing listens on 3004/8004); the local run mode is `.\start.ps1` (backend 8004 with uvicorn `--reload`, frontend 3004 in dev mode). The user validates features against the PRODUCTION deployment, so uncommitted local edits are invisible to him: when he reports a change "didn't appear" ("YOK ÇIKMADI AYARLARDA..."), first establish what is actually running (listening ports/processes, `docker ps`, git status) — the usual cause is the fix sitting only in the local working tree, unpushed; push to main then counts as a production deploy and is offered as an explicit approval-gated step rather than done silently. Confidence: 0.7
